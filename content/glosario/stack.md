## Definición

El stack de un proyecto es el conjunto de tecnologías que se eligen para trabajar: lenguaje, framework, gestor de dependencias, base de datos, herramientas de build y despliegue. No es una lista de moda: cada pieza resuelve una necesidad y condiciona las demás.

## Por qué importa

Define lo que una persona necesita saber para incorporarse al proyecto y lo que la CI debe ejecutar. Cambiar una pieza del stack suele arrastrar a las otras: sustituir el gestor de dependencias cambia los comandos, los archivos de configuración y a menudo el pipeline.

## Ejemplo

Un stack habitual en frontend: TypeScript, React, Vite, npm y Vitest. Un stack fullstack añade una API en Node y una base de datos. En los formularios de una entrevista técnica, «describe tu stack» significa explicar ese conjunto y por qué se eligió.

## Se confunde con

- **Stack trace**: es la pila de llamadas que aparece en un error; no tiene relación con las tecnologías elegidas.
- **Fullstack**: describe un proyecto que incluye cliente y servidor; es una propiedad del alcance, no la lista de tecnologías.
- **TanStack**: es una familia concreta de librerías, no el stack de un proyecto.

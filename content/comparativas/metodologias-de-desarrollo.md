## Contexto

Cuatro siglas que suelen citarse como si fueran la misma cosa: SDD, TDD, DDD y BDD.

## Criterios

Qué problema resuelve cada una, en qué momento actúa y qué artefacto produce.

## Cuándo elegir cada una

SDD para decidir qué construir, DDD para modelar un dominio complejo, BDD para acordar comportamiento y TDD para implementar con tests primero.

## Ejemplos

Una spec antes de escribir código, un modelo de pedido, escenarios Given/When/Then y un test unitario fallido.
